# GEO 实时内测

入口为 https://www.laoyao.cn/geo/ 。点击“实时内测”，输入设置时保存的团队口令即可使用。教学演示保留原有示例。

## 使用与验收

首页内置 10 个测试问题，点击后填入输入框，按“搜索”发起调用。测试内容覆盖概念解释、官方资料、工具比较、地区条件、信息不足和引用复核。

回答完成后，可以查看实际搜索词、接口返回数量、排序分、输入证据、回答段落与引用来源。开启“GEO 透视”，点击回答片段可查看关联选段和原文链接。

六个步骤记录本站执行的检索与生成流程。搜索结果中的排序分保留 0～3 刻度，权威等级保留 0～4 刻度，未知等级单独标注。网页正文和搜索摘要分别标记。服务端验证引用编号存在，完整保留每个内容块的全部有效证据编号；同网页多段证据只在前端合并来源按钮，弹层逐段展示。结论与证据是否充分对应仍需人工复核。搜索结果覆盖范围会影响答案质量。

参考来源卡片、引用弹层和引用汇总页直接显示 DeepSeek 返回的“网页权威”和“搜索排序”。权威值 0 为有效值，未知值单独显示“未知”；API 两项原值与本站百分制六维加权分分别标注。关闭 GEO 透视时，参考卡片仍显示这两项 API 数值。

默认搜索不自动添加 `lang:`，返回的各语言信源共同按 DeepSeek `rerank_score` 排序，语言标签仅供核对。查询保留用户的原始问题和实体，允许规划相关的跨语言等义查询。规划查询先执行操作符清理与校验，再去重并保留最多三条；仅含 `lang:` 等清理后为空的扩展词会跳过，原始规划与跳过理由保留在诊断记录中。简体、繁体与英文网页均可作为回答依据；回答继续按用户提问语言和繁简字形呈现；每次生成的系统指令同时带上语言代码与可读名称（例如 `zh-Hant` 与“繁體中文”），要求正文、标题和强调短语保持对应字形。资料语言由本站按正文、摘要或标题中的常用词和字形特征估计，混合文本与无法确定的字形单独标记。

用户明确指定 `lang:en`、`lang:zh,en`，或要求“只用简体中文资料”“Use only English sources”等时，才向 Search 添加对应语言限制。用户指定的排除条件（例如“不要英文资料”）持续作用于候选与实际读取的段落；Fetch 后发现语言不符合限制的页面不会进入回答。严格条件下缺少资料即提示资料不足。普通语言讨论、输入语言及“请查英文资料”“优先使用”的表述均不会自动变成硬性语种限制；需要限定时可写“只用英文资料”或 `lang:en`。

来源选用采用 API 1.50 分优先、1.00 分兜底。先检查 1.50 分及以上来源，内容可用的精读来源不足五页时，再检查 1.00 分及以上、1.50 分以下的候选，各档默认按 API 分降序。低于 1.00 分的候选保留在记录中。移除了按语言分组排序、首选语言独占证据和跨语言补搜分支；各语言在首次检索中共同参与选源。六维教学实验也使用同一语言约束规则，预览与明确应用的交互保持一致。版本更新会使旧回答缓存失效，费用账本继续保留。

DeepSeek 官方将 API 排序分 1.50 及以上描述为优质结果，本站将其作为优先线，并以 1.00 作为可调整的初始兜底线。最多保留 5 个内容可用的精读来源。1.00 分及以上、1.50 分以下的补充选段须含完整语句，并通过查询主题词预检：从原问题及该网页实际命中的查询提取词项，去掉检索操作符和常见问句词；在移除标题、链接与 URL 后的实际语句中，至少完整命中一个非通用英文或数字词项，或两个不同的中文双字词项，查询仅有一个中文词项时需命中该词项。预检沿用跨语言查询词，语言标签不影响默认选用。此检查衡量词项匹配，结论与证据是否对应继续通过引用原文复核。正文未通过时继续检查长摘要和短摘要。引用卡片、引用弹层及汇总页显示“补充资料”和 API 原分，回答模型同时接收来源档位与分数。某候选缺少有效选段时继续检查后续候选，每次检索最多执行 5 次 Fetch。纯标题、导航标签等内容不单独作为证据；正文缺少有效段落时，依次尝试长摘要和短摘要，并标明“搜索摘要”。每页按问题词命中数选取最多三段完整内容，过程页同时展示采用与排除的段落及原因。没有可用证据时，显示具体的候选数量、未采用原因和下一步建议，保留候选和执行记录，跳过回答生成。原因包括接口无结果、链接全部无效、低于 1.00 分、明确语种条件不符、补充选段主题词匹配不足、正文与摘要无有效段落、正文抓取名额用完及教学实验评分数据缺失。多种原因可同时展示，六步过程页和诊断下载保留同一结果。查询含义不明确时，建议写清推荐对象，例如工具、专家或岗位。原问题不超过 120 字符且规划 JSON 或查询数组格式无效时，直接以原问题检索，不重试模型、不新增模型调用；较长问题使用格式有效的规划查询，保留跨语言改写；规划全部无效时停止搜索并提示缩小范围，避免直接截断原问题而丢失末尾对象与条件。回答正文的格式与引用校验持续生效。

实时版与教学版共用来源卡片、查询扇出、六维权重实验台、段落卡片、引用弹层和六步导航。理解问题展示意图、实体、条件与回答规划；召回展示 Search 实际数量；排序默认显示 API 分、逐查询原始位次与处理依据，另设六维教学实验页签；段落展示采用与排除；综合展示来源映射；引用展示实际来源、未采用原因与六项自查清单。等待时展示六步进度卡，隐藏空引用栏。检索规则升级会使旧版本回答缓存失效，累计费用继续保留。

## 回答内容与排版

回答先给一两句摘要，需要展开时按编号主题小节组织，正文每段只讲一个要点，并列信息可显示为短列表。模型通过 `kind`（`summary`、`paragraph`、`bullet`）、可选 `heading` 和 `emphasis` 返回排版信息；每个内容块仍必须提供有效 `evidence_ids`。简短问题可仅返回摘要。

加粗短语必须在原段落中完整出现，每段最多两处、每处 2～32 字符，总长度不超过该段的三分之一。无效的可选排版信息按普通段落处理；引用编号与正文的验证继续执行。前端以纯文本转义后生成标题、列表和加粗，原文引句保留。摘要、小节和列表中的引用均可打开同一套证据弹层；六步过程的段落数量按实际事实内容块计算。

正文沿用 14px 字号，以段间距、小节标题和少量加粗建立层级。排版参考 [Vane 写作提示](https://github.com/ItzCrazyKns/Vane/blob/master/src/lib/prompts/search/writer.ts)、[Scira 内容渲染](https://github.com/zaidmukaddam/scira/blob/main/components/markdown.tsx)和 [Morphic 搜索回答提示](https://github.com/miurla/morphic/blob/main/lib/agents/prompts/search-mode-prompts.ts)，结合本站按证据编号溯源的结构实现。

## 默认排序与教学实验

实时版默认 `ranking_mode=api`。同 URL 合并时保留最高 API 分记录，并保存每次查询的原始位次、分数、原始字段长度与截断字段。默认稳定排序依次考虑可入选性、优先或补充档位、API 综合分降序、URL。`api_rank` 表示合并池按 API 分重排的参照序，与各次响应的原始数组位次分别记录。

权威等级与日期未知时保持未知，不改变原始 API 分。六维估计不参与默认排序；API 模式收到有效 `weights` 时仍使用默认实验权重作为展示初值。新问题恢复 API 默认排序，教学实验的模式和权重只在明确应用时生效。

### 六维实验与权重

教学实验的初始权重与教学版一致：语义相关性 30、权威可信 20、时效性 15、结构可抽取 15、信息增益 10、多源一致 10。加权分为已知维度的“分数乘权重之和”除以这些维度的权重之和。每项为百分制，未知项单独显示并排除分母；当前启用的维度全部未知时，此页面暂不精读。

DeepSeek 提供综合排序分、权威等级、日期与网页内容。本站据此估计六维分数，过程页逐项显示依据：

| 维度 | 本站计算依据 |
| --- | --- |
| 语义相关性 | API 综合分除以 3，再乘以 100，作为相关性代理。原分也包含权威、时效因素，维度间存在交叉。 |
| 权威可信 | API 权威等级乘以 25；未知等级不参与加权。 |
| 时效性 | 100 除以“1 加距今的天数除以 365”；未知日期和未来日期不参与加权。 |
| 结构可抽取 | Search 返回内容中完整语句的行比例，以及标题、列表、定义标记。 |
| 信息增益 | 本页去重词项中未在其他主机来源出现的比例，估计文本增量。 |
| 多源一致 | 本页去重词项在其他主机来源出现的比例，估计文本共现；具体事实仍需核对原文。 |

分数基于 Search 返回的内容快照。之后 Fetch 返回的正文用于段落抽取，保持本次精排依据可追溯。所有候选保留在结果中，避免切换权重时丢失可晋级的来源。前端与后端使用相同公式、未知值规则与稳定排序规则。教学实验也先选用 1.50 分及以上的可用来源，再补充 1.00 分及以上、1.50 分以下的来源；各档内按实验加权分降序，API 分和 URL 用于稳定比较。

滑块与预设只预览本次候选排名，不发起付费调用，也不改写已经生成的回答。点击“按实验排序重新生成”后，后端按新权重选择精读来源并生成回答，费用计入原有 50 元预算。重新检索时，搜索结果可能变化。返回回答前使用的权重和预览中的权重分别保留，页面明确显示预览状态。实验生成的回答标注“六维教学实验回答”，切回 API 页签仅预览原生分顺序。点击“按 DeepSeek 排序重新生成”后才更新回答。

`POST /geo/api/search` 可附加 `weights` 对象，六个键为 `rel`、`auth`、`fresh`、`struct`、`gain`、`cons`，每项为 0～50 的整数，至少一项大于零。省略时使用默认值。另可附加 `ranking_mode`，允许 `api`（默认）或 `teaching`。权重仅在 `teaching` 模式影响来源选择。无效模式或权重在付费前返回 400；缓存按版本、问题、模式区分，教学模式再区分完整权重，15 分钟内复用同一组合结果。

## 本次处理记录

每次非缓存检索生成一个 `run_id`，私有记录保存在数据卷的 `diagnostics/`，目录权限 700、文件权限 600。记录包括：原始 Search/Fetch 响应、各次请求正文与耗时、模型请求与响应、计费预留和结算编号、搜索规划、链接跳过原因、合并统计及最终回答。鉴权请求头、API Key 和团队口令不进入记录。

记录最长保留 7 天，目录上限 200 MiB，优先清理已结束的旧运行；正在写入的运行不会被清理。达到上限或存储失败时继续正常处理问题，结果明确标记留档不完整，无法追溯的信息保持未知。记录不进入静态站点或 Git 仓库。

引用展示页可下载本次诊断 JSON，路由为 `GET /geo/api/runs/:run_id`，必须有有效内测会话，过期或已清理的记录返回 404。缓存结果继续关联原检索记录，不新增付费调用。本次已结算费用、待确认预留与全站累计费用分别显示。

兼容字段 `language_priority` 固定为 0，`language_supplement`、`supplement_searched` 和 `language_fallback` 固定为 false，前端不据此分组或标记补充信源。`quality.response_language` 独立记录回答语言，`strict_language` 与 `excluded_languages` 记录用户指定的信源约束。

`quality.min_score` 为 1.00，`preferred_score` 为 1.50，`fallback_used` 与 `fallback_read_count` 记录实际精读的补充资料，`insufficiency_reasons` 为包含 `code`、`count`、`message`、`action` 的具体原因数组。来源的 `score_tier` 为 `preferred`、`fallback` 或 `excluded`；补充选段的 `topic_match`、`term_hits` 与 `relevance_terms` 保留预检依据。版本提升使旧的空回答缓存失效，费用账本保持累计。

`processing` 分别记录入口接受、入口跳过、重复出现、唯一 URL 与 Fetch 次数。原始返回数等于入口接受加入口跳过，入口接受等于唯一 URL 加重复出现。页面数量、输入证据段数、回答块数和引用关联数各自使用对应单位。

诊断写入、上游响应解码和下载出口均对当前配置的 Key、访问口令及其 JSON 转义形式进行精确脱敏，嵌套字段及部分 Unicode 转义的 JSON 内容同样处理。业务解析保留协议字段名，日志和下载对凭据匹配的键和值均脱敏。原始指标、费用与其他非敏感内容保留。下载旧记录时也执行当前凭据脱敏。缓存命中时重新检查诊断文件是否仍在保留期与容量范围内；已清理的记录隐藏下载入口。缓存页面显示原检索结算费用，并明确标注本次读取无新增调用。

本版核对范围为引用编号存在及来源对应，尚未执行自动结论支持性核查。

## 密钥设置与更换

1. 登录 [DeepSeek 开放平台](https://platform.deepseek.com/)，在 API Keys 页面创建本项目专用的 Key，并确认账户有可用余额。
2. 在本机双击本目录的 `configure.command`。粘贴 Key，回车；设置至少 12 个字符的内测访问口令，再输入一次确认。输入过程隐藏字符。
3. 密钥保存在本机 `~/.config/laoyao-geo/credentials.json`，权限为 600。完整 Key 和口令保留在本机，避免写入聊天、前端或仓库。
4. 开发阶段可运行 `run-local.command`，通过 http://127.0.0.1:4010/geo/ 验证页面。离线测试不需要真实 Key。
5. 管理员发布当前提交后，停止本机服务，在项目根目录运行 `ruby ops/geo/provision.rb --install`。程序使用现有博客专用 SSH 连接，通过加密连接的标准输入安装配置。

安装程序会先关闭本机付费入口，再把本机累计费用及在途请求的预留费用写入服务器初始预算。安装结果不明确时，本机继续保持关闭，检查网站状态后可再次运行安装程序。更换 Key 或团队口令时重复第 2、5 步，服务器账本和累计费用保留。现有登录会话最长保留 12 小时。

## 50 元预算

金额以整数微元入账，调用前先预留上限，收到可核算用量后结算。SQLite 事务保证并发请求共用同一预算，重启和更新保留账本。每个登录会话每分钟最多发起 5 次搜索，全站同时最多处理 2 个问题；相同问题和权重组合的结果缓存 15 分钟。

按 2026 年 11 月 1 日的[官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)核算：Search、Fetch 每次成功且结果非空的请求为 0.005 元；`deepseek-flash` 按高峰价保守计算，输入每百万 token 2 元，输出每百万 token 8 元。忽略模型缓存折扣和空闲时段折扣，因此页面累计通常高于实际扣款。

一次搜索最多执行 3 次 Search、5 次 Fetch，并调用模型至多两次。最终最多 5 个内容可用来源的选段进入回答；语言不同不会触发额外付费补搜。已尝试但缺少内容或不满足用户明确语种限制的页面保留在候选记录，`attempted_count` 记录尝试页面数量，`read_count` 记录最终精读来源数量。Search 已返回正文时跳过 Fetch。网络超时或结果不确定时保留预留费用，停止后续调用，不自动重试付费请求。异常用量超过预留范围时记录观测费用，并持久暂停后续付费调用。

50 元限制覆盖此应用的受控调用。本 Key 在其他工具中的使用、官方调价及账户充值由 DeepSeek 平台管理。上线后以平台账单复核实际扣款；调价后先更新计费规则，再继续内测。

## 运行和部署

后端使用 Ruby、WEBrick、SQLite，部署为 `geo-api` 容器，由博客容器代理 `/geo/api/`。API Key 只保存在服务器 `/etc/laoyao-geo/credentials.json`，以只读文件挂载；账本、缓存和登录会话保存在 Compose 的 `geo-data` 卷。静态构建排除 `backend/` 和 `ops/geo/`。

常规更新继续运行 `ops/laoyao/deploy.sh`。存在 `/etc/laoyao-geo/enabled` 时自动合并本目录的 Compose 配置。安装或更换配置设置 `.git/laoyao-deploy/reconfigure`，即使提交未变化也重建容器；全部健康检查通过后才清除标记。

专用 SSH 入口增加两个精确匹配的应用操作：`geo-configure` 接收有限长度的 JSON，校验提交、Key 格式、口令和预算；`geo-disable` 停止实时服务、恢复原 Nginx 配置并重新部署博客。其他远程命令继续执行原有部署流程。该连接不提供远程终端。

关闭实时内测并恢复博客：

```bash
ssh -i ~/.ssh/id_ed25519_laoyao_blog_deploy -o IdentitiesOnly=yes -o StrictHostKeyChecking=yes root@39.107.137.177 geo-disable
```
